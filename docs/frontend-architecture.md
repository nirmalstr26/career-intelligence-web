# Frontend Architecture

The CareerAI web UI is a **TanStack Start** (React 19 + Vite) SPA/SSR app that
talks to the CareerAI FastAPI backend. Authentication is **Google-only** and the
session is a backend-managed **HttpOnly cookie**. The Lovable-generated landing
design is preserved; app features are layered on top.

## Stack

- React 19 + TanStack Start (SSR via Nitro) + Vite + TypeScript (strict).
- TanStack Router (file-based routes in `src/routes/`, `routeTree.gen.ts` is
  auto-generated by the router plugin during `dev`/`build`).
- TanStack Query for server-state.
- Tailwind v4 (inline `@theme` in `src/styles.css`) + shadcn/ui.

## Environment

Only **public** values live in the frontend (`src/lib/env.ts`, typed in
`src/vite-env.d.ts`):

| Var | Meaning |
| --- | --- |
| `VITE_API_BASE_URL` | Backend base URL incl. `/api/v1` (e.g. `http://localhost:8000/api/v1`) |
| `VITE_GOOGLE_CLIENT_ID` | Public Google Web client id |

There are **no secrets** in the browser. Copy `.env.example` to `.env` and fill in
your values. `isGoogleConfigured` gates the Google UI so the app still builds and
previews without a client id.

## API client — `src/lib/api.ts`

A thin `fetch` wrapper that:

- always sends the session cookie (`credentials: "include"`),
- serializes/parses JSON,
- normalizes the backend error envelope `{ error: { code, message } }` into a
  typed `ApiError` (with `status`, `code`, `isUnauthorized`, `isForbidden`).

Domain calls live in `src/lib/careerai/client.ts` with types in
`src/lib/careerai/types.ts`; query hooks in `src/lib/careerai/hooks.ts`.

## Authentication — `src/lib/auth/`

- `google.ts` — loads Google Identity Services (GIS) once, browser-guarded, and
  exposes a minimal typed surface (`initialize`, `renderButton`, `prompt`).
- `AuthProvider.tsx` — the auth context (`useAuth`). On mount it calls
  `GET /auth/me` to resolve the session and warms up GIS. It exposes:
  `status` (`loading | authenticated | unauthenticated`), `user`, `student`,
  `onboardingRequired`, `signingIn`, `error`, and the actions `refreshSession`,
  `logout`, `promptGoogleSignIn`, `renderGoogleButton`.
  - The Google callback exchanges the credential at `POST /auth/google`.
  - The session token is **never** read here — it lives in the HttpOnly cookie.
- `GoogleSignInButton` (in `src/components/auth/`) renders the official GIS button
  (real, verifiable ID token) and shows a helpful placeholder when unconfigured.

The landing `AuthCard` is Google-only (email/password inputs removed). The Hero
and Navbar CTAs use `useGoogleSignInCta` to scroll to the sign-in card and trigger
Google One Tap.

## SSR strategy

Auth is resolved **client-side**: `AuthProvider` calls `/auth/me` in a `useEffect`
(effects don't run during SSR), so the server render is always the neutral
`loading` state and never fetches with a user's cookie. All browser-only APIs
(`window`, GIS) are guarded. Route guards redirect **after** hydration.

## Routing & guards

File-based routes under `src/routes/`:

- `/` — landing. Redirects authenticated users to `/onboarding` or `/app/home`.
- `/onboarding` — wrapped in `<Protected mode="onboarding">`.
- `/app` — layout route: `<Protected mode="app"><AppShell/></Protected>`.
  - `/app/` redirects to `/app/home`.
  - `/app/home`, `/app/career`, `/app/missions`, `/app/evidence`, `/app/profile`,
    `/app/diagnostic`.

`src/components/auth/Protected.tsx` is the single client-side guard:

- `app` mode: requires authenticated **and** onboarding complete; otherwise
  redirects to `/` or `/onboarding`.
- `onboarding` mode: requires authenticated **and** onboarding still required;
  otherwise redirects to `/` or `/app/home`.

While the session resolves (or a redirect is pending) a loader is shown so
protected content never flashes.

## Design system

The dark OKLCH theme, fonts, and utilities (`surface-panel`, `gradient-primary`,
`text-gradient`, `hover-lift`) from `src/styles.css` are reused across the app
shell, onboarding, and dashboard. The landing visuals are unchanged.

## Scripts & gates

```bash
npm install          # or: bun install (project default)
npm run dev          # dev server (regenerates routeTree.gen.ts)
npm run build        # production build (also regenerates routes)
npm run typecheck    # tsc --noEmit
npm run lint         # eslint .
```

Run `build` before `typecheck` after adding routes so `routeTree.gen.ts` is
up to date.
